Grafito Innovations

This guide explains the whole EDS setup for the Grafito CAN stepper: what an EDS is, how to import it into a PLC, every object in the dictionary, and how to command motion like a drive profile. You do not need prior CANopen experience to start. Later chapters assume you have read the earlier ones.

Two firmwares, two protocols The production Python product still uses GCSP v1 (GrafitoCANStepper_C3.ino, firmware 1.9). PLC / EDS support is the separate CANopen sketch (GrafitoCANStepper_C3_CANopen, firmware 2.0). Do not mix GCSP and CANopen nodes on the same CAN bus. Flash CANopen firmware before importing this EDS.

Part 1 — Beginner: what you are configuring Beginner

1.1 The hardware in one paragraph

A Grafito CANStepper C3 board is a small CAN node: ESP32-C3 microcontroller, TMC2209 stepper driver, MT6701 magnetic encoder (16384 counts per revolution), and a TCAN3413 CAN transceiver. Several boards can share one CAN cable. A PLC or PC talks to them by sending short CAN frames. The motor does not understand “CANopen” by itself — the firmware on the ESP32 does.

1.2 CAN is the wire. CANopen is the language

Think of three layers:

LayerWhat it isOn this product
Physical CANTwo wires (CAN_H / CAN_L), 11-bit IDs, up to 8 data bytesCAN 2.0A, default 1 Mbps
CANopen (CiA 301)Agreed meaning for those IDs: start node, read a setting, cyclic I/ONMT, SDO, PDO, heartbeat, emergency
Drive profile (CiA 402)Agreed meaning for a motor: enable, move, home, faultpp / pv / hm subset

Without CANopen, a PLC only sees raw frames. With CANopen, the PLC can say “write object 0x607A (target position)” instead of packing bytes by hand.

1.3 What an EDS file is

An Electronic Data Sheet (CiA 306) is a text file that describes one device to a PLC configuration tool. It is not firmware and it does not move the motor. It is a catalogue:

  • who made the device (vendor, product, revision)
  • which bitrates it supports
  • every setting and process value (the object dictionary)
  • which values can ride on cyclic PDOs
  • default CAN identifiers (COB-IDs)

When you import GrafitoCANStepper.eds, TwinCAT, Codesys, TIA Portal, or similar tools build a device tree from that catalogue. The PLC then uses SDO and PDO at runtime against the live node.

Three files are generated from the same object table in canopen402.py:

FileStandardWhat it is
GrafitoCANStepper.edsCiA 306 EDSDevice template. Import this to add the product to the PLC catalogue.
GrafitoCANStepper_Node1.dcfCiA 306 DCFOne instance: node ID 1, 1 Mbps, filled COB-IDs, ParameterValue on every object. Use this when the tool asks for a DCF / “configured device”.
object_dictionary.json / .csvGrafito exportThe same object dictionary as a table. For spreadsheets, reviews, and tools that do not parse EDS.
Analogy The EDS is the datasheet. The DCF is that datasheet filled in for one board on the bus. The object dictionary is the list of registers. SDO is “read/write one register when I ask.” PDO is “keep sending these registers every cycle.” NMT is the on/off switch for the whole node.

1.6 Units you must memorise

CANopen drives use integers, not floating-point degrees on the wire.

QuantityUnitConversion
Position (0x6064, 0x607A)encoder counts16384 counts = 360° = 1 motor revolution
Velocity (0x606C, 0x60FF, 0x6081)counts / seconddeg/s = counts/s × 360 / 16384
Acceleration (0x6083, 0x6084, 0x6085)counts / s²same scale. Default 131072 ≈ 2880 °/s²

Examples: 90° = 4096 counts. 10° ≈ 455 counts. 720 °/s = 32768 counts/s (the default profile velocity).

First practical step Flash firmware 2.0, apply 24 V Vin (USB is data only), terminate the two physical ends of the CAN bus, set the PLC bitrate to 1 Mbps, import the EDS, set node ID 1, then read 0x1000 and 0x1018 before you try to move.

Part 2 — Intermediate: the EDS file and object dictionary Intermediate

2.1 EDS is an INI file

Open GrafitoCANStepper.eds in any text editor. Sections look like [FileInfo], [DeviceInfo], [1000], [1018sub1]. Comments start with ;.

FileInfo

Metadata for the file itself: name, EDS version 4.0, author, dates. PLC tools record this; it does not change runtime behaviour.

DeviceInfo

Tells the tool which baud rates to offer and how many PDOs exist.

KeyThis EDSWhat you set on the PLC
BaudRate_125 / 250 / 500 / 10001 (supported)Match object 0x200E. Factory default is 1 Mbps
BaudRate_10 / 20 / 50 / 8000Do not select these
SimpleBootUpSlave1Node boots to pre-operational and waits for NMT Start
NrOfRXPDO / NrOfTXPDO2 / 2RPDO1+2, TPDO1+2
LSS_Supported0No LSS. Change node ID via 0x2000 + save + reboot
Granularity8Mapping is byte-oriented

Object lists

Three inventories must list every index that later appears as a section:

  • MandatoryObjects — 0x1000, 0x1001, 0x1018 (CiA 301 requires these)
  • OptionalObjects — communication + CiA 402 objects
  • ManufacturerObjects — Grafito-specific 0x2000–0x2019

If an index is in the file but missing from these lists, many importers reject the EDS.

DCF extras (not in the EDS)

The DCF is the EDS plus a commissioned instance. Extra sections:

  • DeviceComissioning (CiA spelling) — NodeID=1, Baudrate=1000 (kbit/s), NetworkName=GrafitoCAN
  • LastEDS — points at GrafitoCANStepper.eds
  • ParameterValue on every object — the live instance. DefaultValue stays the factory EDS default. For node 1 they usually match; for another node ID the COB-IDs and 0x2000 differ.

Regenerate a DCF for another node with render_dcf(node_id=N). Do not hand-edit COB-IDs; they are 0x80+N, 0x180+N, 0x200+N, …

[6040]

Part 3 — Intermediate: CiA 402 drive profile Intermediate

3.1 Why a PLC will not move from “enable bit = 1”

CiA 402 uses a finite state machine. The PLC walks the drive through named states by writing the controlword (0x6040). The drive reports the state in the statusword (0x6041). Skipping steps is ignored.

StateStatusword bits 0–6Hex (plus remote 0x200)Coils / motion
Switch on disabledxxxx 0100 00000x0240Off after boot
Ready to switch onxxxx 0010 00010x0231Still off
Switched onxxxx 0010 00110x0233Power stage ready
Operation enabledxxxx 0010 01110x0237Motion allowed
Quick stop activexxxx 0000 01110x0207Stopping
Faultxxxx 0000 10000x0208Disabled; need fault reset

Bit 4 (voltage enabled, 0x0010) and bit 9 (remote, 0x0200) are also set in the ready / enabled states on this firmware.

3.2 Controlword commands (0x6040)

The command is encoded in bits 0–3 and 7. Other bits (new setpoint, relative, halt) are used only in Operation enabled.

CommandWrite value (typical)Bits that matterFrom → to
Shutdown0x0006xxxx x110SOD → Ready; OE → Ready
Switch on0x0007xxxx 0111Ready → Switched on; also “disable operation” from OE
Enable operation0x000Fxxxx 1111Switched on → Operation enabled
Disable voltage0x0000bit1 = 0Back to Switch on disabled
Quick stop0x0002xxxx x01xOE → Quick stop
Fault reset0x0080bit7 rising edgeFault → Switch on disabled
New setpoint (pp/hm)0x001F0x000F + bit4Starts a position or home
Halt0x010Fbit8Stop, target reached
Relative pp0x005Fbit6 + bit4 + 0x0FTarget is a delta
Memorise this enable sequence Write 0x6040 = 6, then 7, then 15 (0x0F). Read 0x6041 after each step until bits 0–6 equal 0x21, 0x23, then 0x27. Only then write a target.

3.4 Modes of operation (0x6060 / 0x6061)

ValueNameHow you command it

0x6502 (supported modes) = 0x00000025 (bit 0 = pp, bit 2 = pv, bit 5 = hm). Interpolated position, cyclic synchronous, and torque modes are not implemented.

3.5 Profile position recipe

  1. Optional: set 0x6081 (cruise) and 0x6083 (accel) in counts/s and counts/s².
  2. Write 0x6060 = 1.
  3. Walk 6 → 7 → 15 on 0x6040.
  4. Write 0x607A = target counts (absolute unless controlword bit 6 is set).
  5. Write 0x6040 = 0x001F (enable + new setpoint).
  6. Write 0x6040 = 0x000F (drop bit 4; leave enabled). Status bit 12 acks the edge.
  7. Wait until 0x6041 bit 10 (target reached) or 0x6064 is inside tolerance.

3.6 Homing methods (0x6098)

Speeds: 0x6099:01 search, 0x6099:02 zero-window. Timeout: 0x2015. GPIO8 is a strapping pin — it must be HIGH at power-on or the ESP32-C3 may not boot.

3.7 Faults (0x603F and EMCY)

Part 4 — Advanced: PDOs, COB-IDs, SDO and bus timing Advanced

4.1 COB-ID map for node N

Standard 11-bit identifiers. Defaults below are for N = 1 as stored in the EDS. Live firmware adds the actual node ID.

ServiceFormulaNode 1Direction
NMT0x0000x000Master → all / one
SYNC0x0800x080Master → slaves
EMCY0x080 + N0x081Node → master
TPDO10x180 + N0x181Status + position
RPDO10x200 + N0x201Controlword + target position
TPDO20x280 + N0x281Status + velocity
RPDO20x300 + N0x301Controlword + target velocity
TSDO (reply)0x580 + N0x581Node → master
RSDO (request)0x600 + N0x601Master → node
Heartbeat0x700 + N0x701Node → master (1 byte NMT state)

Heartbeat payload: 0x00 boot-up, 0x04 stopped, 0x05 operational, 0x7F pre-operational.

NMT payload (ID 0x000): byte0 = command (0x01 start, 0x02 stop, 0x80 pre-op, 0x81 reset node, 0x82 reset comm), byte1 = node ID or 0 for all.

Why GCSP and CANopen cannot share a bus GCSP uses CAN ID = (node_id << 6) | msg_id. That range collides with CANopen SYNC (0x080), EMCY, TPDOs and heartbeats. Flash one protocol per network.

4.2 PDO mapping encoding

Each mapping entry is a 32-bit value: bits 31–16 = index, 15–8 = subindex, 7–0 = bit length.

ObjectStored valueDecoded
0x1600:010x60400010Controlword 0x6040:00, 16 bits
0x1600:020x607A0020Target position 0x607A:00, 32 bits
0x1601:010x60400010Controlword, 16 bits
0x1601:020x60FF0020Target velocity, 32 bits
0x1A00:010x60410010Statusword, 16 bits
0x1A00:020x60640020Position actual, 32 bits
0x1A01:010x60410010Statusword, 16 bits
0x1A01:020x606C0020Velocity actual, 32 bits

RPDO1 payload (8 bytes): U16 controlword | I32 target_pos | U16 pad. RPDO2 replaces the I32 with target velocity. TPDOs use the same layout with statusword + actual value.

Transmission type 255 = event / manufacturer (async). Firmware also emits TPDOs about every 20 ms while NMT is operational. RPDOs are ignored unless the node is operational. Mapping is fixed in firmware; SDO writes to 0x1600/0x1A00 are read-only.

4.3 SDO protocol the EDS implies

All configuration objects are reached with expedited SDO except visible strings (0x1008/09/0A), which use segmented upload.

Request  ID 0x600+N
  cmd, index_lo, index_hi, sub, d0, d1, d2, d3

Upload request          cmd = 0x40
Expedited download 4 B  cmd = 0x23   (3 B 0x27, 2 B 0x2B, 1 B 0x2F)
Download OK             cmd = 0x60
Expedited upload 4 B    cmd = 0x43
Initiate segmented      cmd = 0x41 + size
Abort                   cmd = 0x80 + abort code

Common abort codes: 0x06020000 no object, 0x06090011 no subindex, 0x06010002 write to RO, 0x06090030 value rejected (bad bitrate, non-power-of-two microsteps, illegal mode).

4.4 NMT vs 402 — two state machines

Beginners mix these up. They are independent:

  • NMT (network): boot → pre-op (SDO yes, PDO no) → operational (SDO + PDO) → stopped (almost mute) → reset.
  • 402 (drive): switch-on-disabled → … → operation enabled / fault.

You can SDO-enable the 402 machine while still in NMT pre-op (useful for commissioning). Cyclic RPDO motion only works after NMT Start (0x01).

4.5 Editing the EDS (when you are allowed)

Safe edits: comments, ParameterName text, FileRevision, description. Dangerous edits: removing an object the firmware still implements, changing DataType, or advertising a PDO map the stack does not use. After any object change, regenerate EDS, DCF and the object-dictionary exports together with write_canopen_descriptions() so the Python tests, PLC files and firmware stay aligned.

DummyUsage Dummy0002–0007 = 1 lets tools pad PDO slots. Leave as shipped.

Part 5 — Advanced: PLC import and first-motion recipes Advanced

5.1 Wiring and tool setup (all brands)

  1. Flash GrafitoCANStepper_C3_CANopen (Arduino FQBN esp32:esp32:esp32c3:CDCOnBoot=cdc).
  2. Apply Vin 5–24 V (typically 24 V). USB-C does not power the MCU for reliable programming or motion.
  3. CAN: twisted pair, 120 Ω only on the two physical ends. On-board 0 Ω termination jumper is fitted by default — remove it on mid-chain boards.
  4. PLC CAN adapter: 1 Mbps, 11-bit, no 29-bit, same ground reference.
  5. Import GrafitoCANStepper.eds as the device type. If the tool wants a configured node / DCF, import GrafitoCANStepper_Node1.dcf (node 1, 1 Mbps). For another node ID, regenerate the DCF — do not reuse node 1 COB-IDs.
  6. Set slave node ID to the value stored on the board (default 1).
  7. Scan / go online. Read 0x1018. If vendor/product mismatch, you have the wrong EDS or the wrong firmware.

5.2 Codesys (CAN bus + CiA 405 / 3S CANopen)

  1. Add a CANopen Manager under the CAN interface. Bitrate 1000 kbit/s.
  2. Right-click manager → Add Device → Install vendor EDS → select GrafitoCANStepper.eds.
  3. Add “Grafito CANStepper C3” as a slave. Node ID 1. Heartbeat consumer 1.5× 1000 ms is a good watchdog.
  4. Map RPDO1 (controlword + target pos) and TPDO1 (statusword + position) into your IEC program as integers.
  5. Startup SDO list (optional): 0x2003 run current, 0x2006 invert, 0x200C endstop, 0x6081 speed, 0x6060 = 1.
  6. NMT Start is usually sent by the manager automatically.

5.3 TwinCAT 3 (Beckhoff)

  1. I/O → Devices → CAN → right-click → Import EDS.
  2. Insert the box, set Node ID and 1 Mbaud on the adapter (EL6751, FC510x, CX CAN, …).
  3. Process data tab should show the four PDOs. Create PLC variables linked to 0x6040, 0x6041, 0x607A, 0x6064.
  4. Free-run or start the NC/PLC. Use a small state machine FB: shutdown / switch on / enable / new setpoint.

5.4 TIA Portal / other Siemens CAN (via gateway)

S7-1200/1500 do not speak CiA 402 natively on a random CAN dongle. Typical paths: a dedicated CANopen master (HMS, Ixxat, Siemens CM CANopen) that imports the EDS, or a Linux SoftPLC (Codesys) as gateway. Import the same EDS on that master. Do not expect a raw “CAN_SEND” FB to honour the 402 state machine unless you write it yourself.

5.5 IEC-style enable and jog (pseudocode)

VAR
  cw AT %QW : UINT;     (* 0x6040 via RPDO1 *)
  sw AT %IW : UINT;     (* 0x6041 via TPDO1 *)
  tgt AT %QD : DINT;    (* 0x607A *)
  pos AT %ID : DINT;    (* 0x6064 *)
  step : INT;
END_VAR

CASE step OF
  0: cw := 16#0006; IF (sw AND 16#006F) = 16#0021 THEN step := 1; END_IF
  1: cw := 16#0007; IF (sw AND 16#006F) = 16#0023 THEN step := 2; END_IF
  2: cw := 16#000F; IF (sw AND 16#006F) = 16#0027 THEN step := 3; END_IF
  3: tgt := pos + 455;  (* +10 degrees *)
     cw := 16#001F;     (* new set-point *)
     step := 4;
  4: cw := 16#000F;     (* drop bit 4 *)
     IF (sw AND 16#0400) <> 0 THEN step := 5; END_IF
  5: (* dwell / next move *)
END_CASE

IF (sw AND 16#0008) <> 0 THEN  (* fault *)
  cw := 16#0080; step := 0;
END_IF

5.6 USB serial bridge (no PLC, same objects)

Firmware still prints and accepts hex lines: <CAN_ID hex> <0|1> <payload hex>. Opening the USB-JTAG port resets the C3 — wait for # CAN started and heartbeat 0x7F.

python3 tools/canopen_bringup.py /dev/ttyACM0 --node 1
# identity only; add --move-deg only after invert is verified

Example SDO read of device type on node 1:

# expect 581 0 4300100092010400   → 0x00040192

5.7 Recommended first-commission checklist

  1. Read 0x1000, 0x1018, 0x2016, 0x2017 (encoder OK).
  2. If 0x2018 (endstop) is 1 and you are not at a real home, write 0x200C = 0 for the first jog.
  3. Set 0x2003 to a modest current (30) and 0x6081 to ~2275 (~50 °/s).
  4. Enable 402. Confirm 0x6041 = 0x0237. Coils should hold; shaft should not run.
  5. Command +455 counts. If the encoder moves the other way, abort, set 0x2006 = 1, save, reset, retry.
  6. Only then raise speed/current and switch to RPDO cyclic control.

6.2 What this EDS does not claim

  • No CiA 402 interpolated position (mode 7), cyclic synchronous position/velocity, or torque mode.
  • No safety (STO, CiA 402 Safety / FSoE).
  • No LSS node-ID assignment over CAN.
  • No dynamic PDO remapping.
  • No official CiA vendor ID yet (0x5A3 is a placeholder).
  • Leader/follower (GCSP FOLLOW) is not exposed in CANopen.

6.4 Regenerating the EDS, DCF and object dictionary

cd can_stepper

The pytest suite checks that every object in the Python dictionary appears in the EDS and DCF, that the DCF has DeviceComissioning + ParameterValue, that the JSON/CSV catalogues match, that identity constants match the firmware header, and that a virtual slave performs NMT, SDO, 402 enable, PDOs and homing.
